# Sesión 07 - Actualización del Contexto y Reevaluación Extraordinaria

# Objetivo de la sesión

Validar el funcionamiento del Contexto Semanal utilizando una situación real y analizar cómo debe reaccionar el Sistema de Activación cuando ocurren cambios importantes durante la semana.

La sesión permitió distinguir entre la actualización normal del contexto y la necesidad de realizar una reevaluación extraordinaria del Sistema de Activación.

---

# Contexto de la semana

Inicialmente se esperaba un viaje a mina que reduciría significativamente la disponibilidad durante varios días.

Sin embargo, antes de realizar el ejercicio dicho viaje fue postergado.

Esta situación permitió comprobar cómo el sistema debe reaccionar cuando un cambio importante modifica la disponibilidad prevista.

---

# Construcción del Contexto Semanal

Se realizó una primera prueba utilizando información real de la semana.

## Disponibilidad

### Trabajo (E2I)

Semana de carga habitual.

Actividades principales:

- mejoras sobre el sistema de Vaki;
- pruebas en Diciembre.

No se identificó una sobrecarga importante.

---

### Docencia

El ciclo todavía no comienza.

Sin embargo, inició el proceso de postulaciones para Jefaturas de Práctica.

Se considera una pequeña carga administrativa adicional.

---

### Tiempo personal

Al cancelarse el viaje a mina se recuperó la disponibilidad inicialmente comprometida.

Este cambio constituye una modificación importante del contexto.

---

## Estado de proyectos

Se identificó un único evento relevante.

### Proyecto Fux

Se programó una reunión para presentar un dashboard y recibir feedback.

Este evento puede generar nuevas tareas o cambios dentro del proyecto.

Los demás proyectos permanecen sin cambios significativos.

---

## Estado personal

No se identificaron cambios relevantes.

Se asume una condición habitual de salud y energía.

---

# Actualización continua del Contexto

Durante la discusión se llegó a una conclusión importante.

El Contexto Semanal no permanece fijo durante toda la semana.

Puede actualizarse continuamente conforme aparecen nuevos eventos.

Ejemplos:

- cancelación de un viaje;
- aparición de nuevas reuniones;
- cambios importantes en un proyecto;
- situaciones personales.

Por tanto, el Contexto debe entenderse como información dinámica.

---

# Reevaluación extraordinaria

Se identificó que actualizar el Contexto no implica necesariamente volver a ejecutar el Sistema de Activación.

La mayoría de cambios únicamente modifican el contexto registrado.

Sin embargo, algunos eventos justifican una nueva evaluación.

---

# Criterio de reevaluación

Se concluyó que el criterio no depende del tipo de evento.

Depende del efecto que dicho evento produce sobre el sistema.

Una reevaluación extraordinaria debe ejecutarse únicamente cuando un cambio modifica de forma significativa alguno de los siguientes aspectos:

- tiempo disponible;
- capacidad o energía;
- compromisos asumidos.

---

# Ejemplos

## No requieren reevaluación

- cambio menor de horario de una reunión;
- pequeñas correcciones dentro de un proyecto;
- modificaciones rutinarias del trabajo.

Estos cambios únicamente actualizan el contexto.

---

## Sí requieren reevaluación

- cancelación o incorporación de un viaje importante;
- asignación de un nuevo curso;
- aceptación de un proyecto que demanda capacidad significativa;
- enfermedad u otra situación que reduzca notablemente la capacidad disponible.

En estos casos puede ser conveniente volver a ejecutar el Sistema de Activación antes de la siguiente revisión semanal.

---

# Regla preliminar del Sistema de Activación

Se propone la siguiente regla de funcionamiento.

> El Sistema de Activación se ejecuta periódicamente durante la Revisión Semanal y, de forma extraordinaria, únicamente cuando un cambio modifica significativamente la capacidad disponible o el conjunto de compromisos del sistema.

Esta regla evita reaccionar innecesariamente ante cambios menores y mantiene la estabilidad del sistema.
