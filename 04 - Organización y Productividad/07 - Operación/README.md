# Operación del sistema

Esta carpeta contiene el estado operativo de la semana. Durante el piloto, el sistema utiliza solo dos superficies:

1. [`../06 - Inbox/Inbox.md`](../06%20-%20Inbox/Inbox.md) para capturar información nueva.
2. [`2026-08-17 - Semana 01.md`](2026-08-17%20-%20Semana%2001.md) para Contexto, Activación, objetivos, planificación, ejecución y evaluación.

El calendario continúa siendo la fuente maestra de eventos y horarios. El tablero semanal solo resume las ventanas que cambian decisiones.

## Arranque de la semana

Abrir el tablero semanal y completar su bloque `Arranque en 15 minutos`:

1. mirar el calendario;
2. resumir el Contexto;
3. seleccionar pocos proyectos activos;
4. escribir uno o más objetivos ejecutables por proyecto;
5. proteger compromisos con presión;
6. preparar una primera sesión razonable.

No es necesario completar cada campo. Un dato se añade solo si cambia una decisión o reduce fricción.

## Durante la semana

### Cuando aparece algo nuevo

Añadir una línea al Inbox y volver a lo que se estaba haciendo.

### Cuando aparece una ventana libre

Abrir `Qué hago ahora` en el tablero semanal y elegir entre los objetivos ejecutables. La salida también puede ser preparación o descanso.

### Al cerrar una sesión

1. actualizar el estado del objetivo;
2. dejar una nota de reentrada solo si ayuda;
3. capturar cualquier trabajo nuevo;
4. registrar una línea en `Sesiones y evidencia`.

### Cuando cambia la realidad

```text
Cambio pequeño
→ ajuste local

Cambio que invalida parte del plan
→ replanificar el tablero

Cambio que altera capacidad o compromisos
→ reevaluar proyectos activos
```

## Cierre del piloto

El domingo se completa `Cierre y feedback`. Los problemas se clasifican antes de cambiar el diseño:

- concepto;
- implementación/herramienta;
- hábito;
- dato innecesario;
- información faltante.

La primera semana busca evidencia, no una operación perfecta.
